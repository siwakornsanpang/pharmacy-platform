# Content publication and HTML integration contract

Task3a owns backend safety. Task3b must implement equivalent app-local runtime/rendering policy using only the pure exports of `@pharmacy/contracts/content`; contracts contain no DOM, framework or sanitizer runtime dependencies.

## Deployment configuration

`CONTENT_IMAGE_SOURCES` is an optional JSON array of `{ "origin": "https://app.example.test", "pathPrefix": "/media/" }` rules. Examples are synthetic, not deployment defaults. Supply actual reviewed nonsecret app/public-media/storage origins and finite public object prefixes through deployment configuration. Each origin is exact HTTPS, no credentials, explicit port, wildcard, query, fragment or path. Prefixes consist of slash-delimited alphanumeric/underscore/hyphen segments, end in `/`, cannot be `/`, and cannot contain `sign`, `private` or `authenticated` segments. Up to20 rules are accepted; malformed configuration fails startup. App/storage hosts and buckets are not inferred from CORS, Next image settings, Supabase configuration or caller input.

The first rule's origin is the base for root-relative image references. Use the pure `resolveContentImage(value, validatedSources)` result as the emitted src; a boolean check alone is insufficient. Root-relative references become an approved absolute URL, so public/staff document origins cannot change the requested authority. Put the public app rule first if root-relative app media is expected. Images require a configured origin AND matching public path prefix; query/fragment URLs, signed/private paths, data/blob URLs, protocol-relative references, backslashes, credentials, explicit ports and encoded path ambiguity are rejected. Missing configuration means `[]`: all rich-text images are removed while safe text remains.

Image paths undergo one strict UTF-8 percent decode before configured-prefix and case-insensitive forbidden-segment checks. Only nonempty Unicode letter/number/mark or unreserved (`_.~-`) segments are supported; ordinary encoded letters/hyphens and Unicode filenames emit canonical percent encoding. Malformed escapes/UTF-8, residual percent/nested encodings, dot segments, empty internal segments, reserved separators and encoded private/sign/authenticated segments are rejected. Unsupported legacy filename forms (including spaces, literal percent and reserved punctuation) require migration reporting, not silent trust. Canonical output is stable on repeated sanitization. Reads preserve stored source. Task6 separately authorizes asset identities/references; URL trust never grants ownership.

Backend uses `createRichTextSanitizer(config.contentImageSources)` once during composition, returning the single-argument `sanitizeRichText(html)` function. No DOMPurify global hooks or mutable per-request configuration are used. Task3b must use equivalent validated nonsecret trust for server, browser, staff preview and editor load/export boundaries, without shipping backend secrets or jsdom to client bundles.

## HTML policy and intentional removals

Preserve safe paragraphs/br/headings1–6, strong/b/em/i/u/s/strike, sub/sup, ol/ul/li, span, blockquote/pre/code and approved anchors/images/video iframes. Retain only known Quill alignment/indent1–8/direction/font/syntax/UI/video classes, `li[data-list=ordered|bullet]`, and `contenteditable=false` on Quill UI spans. Inline styles permit only the eight font sizes16,18,20,24,28,32,48,64px and safe3/6-digit hex/integer RGB foreground/background colors. Image/iframe dimensions are decimal positive integers≤4096; images retain alt text. Active nodes/attributes, arbitrary styles/classes/data/ARIA, SVG/MathML/formulas, srcset/picture/source, IDs/names and event handlers are removed. New-window links use `noopener noreferrer`; only HTTP/HTTPS/mailto/tel links survive. Quill-accepted sms links/data images are intentionally removed.

Video iframe sources require HTTPS exact `www.youtube.com` or `www.youtube-nocookie.com` `/embed/<id>` with finite bounded playback query tokens, or `player.vimeo.com/video/<digits>/` with optional trailing slash and no query. Unknown/HTTP embeds are removed without upgrading/canonicalizing them. Maps are a separate policy.

## Maps and detail consumers

Public settings now require `googleMapsEmbedUrl: GoogleMapsEmbedUrl | null`. Backend derives it from stored `googleMapsEmbed`: accept exact HTTPS `www.google.com/maps/embed` with a nonempty query≤2048 characters and no fragment delimiter (including a bare trailing `#`), credentials or port. Exactly one iframe snippet may supply its src only; extra markup/children/iframes are rejected, other attributes never grant rendering authority. Validated Maps values emit canonical URL.href (lowercase scheme/host, normalized path/query encoding), and the query bound applies to that canonical URL; every non-null result matches the public property schema. Unsupported/empty values produce null; storage/admin raw source is preserved. `googleMapsUrl` remains separate navigation data. Task3b renders the validated embed URL with fixed JSX iframe attributes. Migration validation must report unsupported nonempty legacy shapes for review.

The26 frozen legacy GETs are active with explicit safe DTOs. Lists of news/medicine/public-project/honor exclude full rich bodies. The reviewed27th public GET `/api/honor/:id` returns `HonorPublicDetail`, sanitizing `fullDetail`, preserving plain `awardDetail`, excluding originals. Task3b loads that detail only when a recipient modal is selected; no per-row prefetch/N+1 list loading. All detail queries accept no query keys. Hidden article IDs return404; undeclared detail queries return400 before lookup. Public/article metadata must use these same filtered detail endpoints.

## Write boundary and later gates

Task6 must invoke `sanitizeContentRichFields(family,input,configuredSanitizer)` after strict decoding and Media authorization, before persistence. Only article `content` and honor `fullDetail` are HTML. Names, excerpts, awardDetail, background and descriptions remain literal data; Task3b must render them as text, including SweetAlert text/titleText. The boundary validates calendar semantics for `publishedAt`/`announcedAt` with shared `isContentTimestamp`/`isContentDate`; JSON schema date/timestamp primitives remain lexical and do not replace these predicates. Mutation HTTPs requiring Media remain guarded503.

Backend evidence includes genuine RED/GREEN, real disposable SQL/app.inject publication/projections/counts/clock and byte-exact installed Quill2.0.3 formula/video export interpolations through callable write and legacy read. Task3b still owes actual installed editor/browser load/export/render behavior and browser-bundle validation; no KaTeX or formula support was added. Target visuals, final consumer/revision integration, Media, final unreleased0009, controlled migration validation and deployment checks remain with their respective owners.
